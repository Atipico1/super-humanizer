# Fable 5.1에서 먼저 볼 곳

반복 대조와 나열 뒤 총평을 먼저 보고, 내용 없는 예고도 확인한다. 아래 형태는 조건부 점검 대상이다. **전은 실제 초안 발췌, 후는 편집 제안**이다. 예시의 결과를 새 모델 윤문 성능으로 해석하지 않는다.

## 1. 같은 문단 안에서 대조를 두 번 완성하기

**눈여겨볼 형태:** '배운 것이 아니다 → 스스로 얻었다'를 말한 직후 '이론이 아니다 → 현장에서 확인된다'로 같은 출처를 다시 설명한다.
**문제와 수정:** 같은 논거가 반복되면 대조 하나를 남기고 다른 쪽은 직접 서술한다. 출처·경험·신뢰의 이유를 삭제하지 않는다.

전: “그래서 오히려 믿음이 간다. 이론에서 내려온 규칙이 아니라 실제 글쓰기 현장에서 매번 확인되는 원칙이기 때문이다.”
후: “그래서 오히려 믿음이 간다. 실제 글쓰기 현장에서 매번 확인되는 원칙이기 때문이다.”

**적용 문맥:** 이 문장 앞에서 이미 책이나 스승에게서 배운 것이 아니라 직접 쓰고 고치며 얻은 원칙이라고 설명했다. 그 앞 설명이 없으면 동일한 삭제를 적용하지 않는다.
**유지:** 같은 글의 “정보 자체가 아니라 그 정보를 둘러싼 나만의 맥락이 글을 살린다.”는 무엇이 글을 살리는지 설명하는 핵심 구별이다. 대조 구문이라는 이유로 없애지 않는다.

## 2. 목록을 예고한 뒤 다시 예고하기

**눈여겨볼 형태:** 소제목이 변화·방법·이유의 목록을 예고했는데 다음 독립 문단도 같은 예고를 한다.
**문제와 수정:** 실제 항목에 도달하기 전에 같은 안내를 거듭 읽게 한다. 소제목과 도입을 합치되 화자의 표현과 실제 항목은 보존한다.

전: 소제목 “블로그가 바꿔놓은 세 가지” → “돌이켜보면 블로그는 나를 조용히 바꿔놓았다.” → “첫째, 매일 글을 쓰는 습관이 생겼다.”
후: 소제목을 “블로그가 나를 조용히 바꾼 세 가지”로 합치고 첫 번째 변화부터 시작한다. 나머지 항목도 그대로 둔다.

**유지:** 목록의 적용 대상·순서·선정 이유를 설명하는 도입은 항목만으로 전달되지 않는 정보다. 도입이라는 이유로 생략하지 않는다.

## 3. 나열과 총평의 골격을 반복하기

**눈여겨볼 형태:** 여러 항목을 나열한 뒤 그 의미를 총평하는 구성이 절마다 반복된다. 결말에서도 항목·요약·교훈이 거듭 붙는지 본다.
**문제와 수정:** 각 항목이 다른 정보를 주는지, 총평이 새 해석이나 행동을 더하는지 확인한다. 내용이 겹치는 총평만 덜고, 실제 항목 수를 임의로 줄이지 않는다.

전 → 후 **(설명용 구성 예시):** “매일 쓰고, 매일 고치고, 매일 읽었다. 쓰기와 고치기와 읽기를 날마다 반복했다.” → “매일 쓰고, 매일 고치고, 매일 읽었다.”

**유지할 실제 예:** “Ask GN — 개발자들이 서로 질문하고 의견을 나누는 공간 / Show GN — 직접 만든 프로젝트나 서비스를 소개하는 공간 / 긱뉴스 Focus — 짧은 뉴스 요약을 넘어, 하나의 주제를 깊이 다루는 심화 콘텐츠”는 서로 다른 기능이다. 세 항목이라는 이유로 합치지 않는다.
**또 다른 유지 사례:** 맥락·대조·솔직함이라는 원칙을 “이건 내 맥락인가?” 같은 점검 질문으로 바꾸는 결말은 사용 방법을 보탤 수 있다. 목록과 같은 단어가 나온다는 것만으로 삭제하지 않는다.

## 부호와 리듬

엠대시가 여러 문장의 삽입 설명에 반복되면 명사와 설명을 직접 연결할 수 있는지 본다. 위 Ask GN 목록처럼 항목과 정의를 구분하는 사용까지 일괄 삭제하지 않는다. 독립 단문을 모두 합치거나 글 전체를 더 짧고 무뚝뚝하게 만들지 않는다.
